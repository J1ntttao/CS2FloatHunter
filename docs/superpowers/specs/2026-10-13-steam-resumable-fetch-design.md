# Steam 数据抓取中断/超时后继续设计

## 目标

Steam 代理中断、请求超时或部分商品抓取失败后，用户可以在网页上点击“继续获取失败项”，复用已经成功获取的数据，仅重新请求失败、超时和中断时尚未完成的商品。整批“开始搜索”仍可用于从头重跑。

## 范围

本设计覆盖网页 `/api/hunt` 主流程，包括“仅 Steam”和“BUFF + Steam 比价”。旧的 `/api/resolve` BUFF 配方解析接口不纳入本次恢复能力。

## 交互

页面保留“开始搜索”和“停止搜索”，新增按需显示的“继续获取失败项”。当本次搜索因代理中断、单项超时、请求失败或材料不足结束，并且服务端提供恢复标识时，页面保存当前搜索参数并显示继续按钮。点击继续会创建新的 SSE 连接，使用同一搜索参数和恢复标识；成功项不重复抓取。

成功完成后隐藏继续按钮。点击“开始搜索”会清空旧恢复状态并重新执行整批搜索。停止搜索只取消当前连接和服务端任务，若已经形成检查点则保留继续入口。

## 服务端检查点

服务端在内存中保存最近一次 `/api/hunt` 搜索的检查点。检查点按搜索配置隔离，包含：

- 恢复 ID、搜索参数摘要和当前配方计划标识；
- 每个材料/商品的名称、英文名、磨损区间、市场来源和抓取结果；
- 成功材料的候选挂单和失败/中断材料的错误信息；
- 可供最终求解使用的候选池及 `perItem` 状态。

每完成一个材料的市场请求就更新检查点。继续请求验证恢复 ID 与搜索参数匹配，然后跳过成功项，重试其余项，重新组装候选池并执行现有求解逻辑。检查点只存服务内存，服务重启后失效；新搜索会替换旧检查点。

## 失败和超时

单个材料失败、超时或代理中断会记录为可重试项。任务被取消时，已完成项保留，尚未完成项标记为中断。若所有材料已处理但候选不足，结果同时返回已有候选与可继续的材料清单；继续请求只补抓这些材料。

不可恢复的输入错误（链接、磨损值、登录态缺失、无可用材料区间等）不生成继续入口。代理恢复后，用户可直接修改代理设置再点击继续。

## API 数据流

`/api/hunt` 增加可选恢复参数（恢复 ID），并在 `error` 或 `done` 相关事件中返回恢复信息：恢复 ID、是否可继续、待重试材料摘要。继续请求沿用原始搜索参数，服务端从检查点恢复。

页面继续按钮使用与普通搜索相同的 SSE 事件处理器，避免重复实现结果渲染；请求建立前只改变恢复参数，服务端决定哪些项需要重新抓取。

## 测试

增加服务端/流程测试，验证：

1. 已成功的材料在继续请求中不会再次调用市场接口；
2. 失败材料会在继续请求中重新获取并合并到候选池；
3. 代理中断/任务取消后检查点仍可继续；
4. 恢复 ID 与搜索参数不匹配时拒绝恢复；
5. 页面只在服务端返回可恢复信息时显示继续按钮，迟到的旧 SSE 事件不会污染新任务；
6. 现有搜索、停止和结果渲染测试继续通过。
