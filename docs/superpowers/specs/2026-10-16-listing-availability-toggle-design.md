# 挂单在售复核开关设计

## 目标

在网页搜索条件中增加“检查挂单是否仍在售”开关，默认开启。开启时保持现有行为：搜索完成前复核最终配方中的挂单，移除已被买走的挂单并重新求解；关闭时跳过这一步，直接使用当前搜索快照。

## 方案

网页新增一个默认勾选的 checkbox。`startSearch` 将其状态作为 `verify_availability=1|0` 查询参数发送，并在恢复搜索时沿用本次搜索的状态。服务端将参数纳入恢复断点签名，避免用不同复核策略复用同一断点。

猎取逻辑接收 `verifyAvailability`，默认值为 `true` 以兼容已有调用方。为 `false` 时不调用市场适配器的 `verifyListing`，结果中的 `availability` 标记为跳过并保留既有结果结构；为 `true` 时执行现有复核、替换和不足报错逻辑。

结果摘要根据状态显示“已复核……”或“已关闭在售检查，结果按搜索快照返回”，让用户知道结果是否经过实时库存确认。

## 验证

增加网页/请求断言，确认开关默认开启、状态传入 API、恢复请求保持状态；增加猎取逻辑断言，关闭时不会调用 `verifyListing`，默认路径仍执行复核。运行相关测试和完整 `npm test`。
